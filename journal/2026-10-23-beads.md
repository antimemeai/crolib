# Beads issue tracking

The operator asked for a bead recording finite-universe negative variance
components, which came out of the salib G-theory fix. crolib had no beads
board, and the home-level `~/.beads` points at a Dolt database (`gt`) that the
local server does not serve; that one was left untouched. Ran
`bd init -p crolib`, following the per-project pattern used in mojave,
deleuze and rhizome.

bd 0.58 made commits on its own (`bd init`, `bd: backup`) and pushed one of
them. It also set `core.hooksPath` to `.beads/hooks`, added Dolt ignores to
`.gitignore`, and appended a 113-line generic block to `AGENTS.md`. That block
repeated `~/AGENTS.md` and contradicted this repo's `issues/` line, so it is
replaced, between bd's markers, by a short pointer. Beads holds discrete work
items. `issues/README.md` stays the narrative capability queue taken from the
design.

Filed crolib-3bk (feature, P2): admit negative components in finite-universe
designs within the PSD bound. In a balanced crossed design the eigenvalues of
Cov(y) are the expected mean squares at the design's counts (checked
symbolically). An infinite universe therefore requires every component to be
≥ 0, while a finite panel of N levels allows bounded negative dependence,
e.g. σ²(pi) ≥ −σ²(pir)/N_r. `bd backup` writes the board into the tracked
`.beads/backup/`.

## Database misplaced by a shared port (fixed)

`bd init` ran while deleuze's Dolt server was listening on the default port,
3307. bd connected to that server and created the `crolib` database inside
deleuze's data directory (`deleuze/.beads/dolt/crolib`). When that server
stopped at 07:04, bd started crolib's own server from `crolib/.beads/dolt`,
which had no database, and every bd command failed with "database crolib not
found".

I declined doctor's suggested fix (`rm -rf .beads/dolt && bd init`), because
it would have discarded comments made after the last backup.

Fix:
- stopped crolib's empty server;
- copied the 636 KB database into `crolib/.beads/dolt/crolib`, while no
  server had deleuze's directory open;
- set a dedicated port with `bd dolt set port 13311`, following mojave and
  rhizome; ports 13307–13310 and 43387 are in use.

Both beads and every comment are intact. The original copy remains in
deleuze's data directory; deleting it is the operator's decision, since that
directory belongs to deleuze. deleuze itself still uses the shared default
port.
